### Спірні рішення і знахідки

1. **`next/dynamic` не використано, хоча завдання цього вимагало.** З ним canvas зʼявлявся
   через ~450 мс після старту інтро: `dynamic()` працює через Suspense, і React повертався
   до цієї межі вже після гідрації решти сторінки. Зі звичайним `import()` у стані це ~50 мс,
   тобто розряди отримали на 0.4 с більше екранного часу. Результат той самий: окремий
   lazy-чанк, на сервері не рендериться. Якщо `next/dynamic` принциповий, це заміна в одному
   місці, але розряди будуть помітні лише з ~0.9 с.
2. **Чанк і силует запитуються одразу при завантаженні модуля**, не чекаючи гідрації, і
   лише якщо на `<html>` немає класу `intro-seen`.
3. **Статичний фолбек відрізняється від попереднього інтро розміром логотипа**: він тепер
   великий (312px замість 148px) в обох режимах, бо розмір закладається ще в серверний HTML,
   до того як відомо, чи є WebGL. Таймінг у фолбеку старий.
4. **Логотип тепер над текстом** (`z-index`). Через більший логотип рядок, що друкується,
   на початку зменшення лягав поверх плитки; тепер він виходить з-за неї. На кадрі 1800 мс
   перша літера ще прихована.
5. **Світінь формально три**: фонове мʼятне (було), `drop-shadow` логотипа (було) і світіння
   розрядів. Усі мʼятні й накладаються в одну пляму; старі я не прибирав.
6. **Старт розрядів блокує головний потік на ~120–160 мс** (створення контексту й
   компіляція шейдера), на цій машині це припадає на перші 120 мс інтро. На слабшому залізі
   може бути довше.
7. **Блокування скролу під час інтро насправді не працює, і не працювало до моїх змін.**
   `IntroAnimation` ставить `body.style.overflow = "hidden"`, але ефект у `Nav.tsx:69` одразу
   після цього скидає його в `""`. Під час інтро `body` без `overflow` у всіх замірах. Не
   виправляв: це `Nav.tsx`, поза завданням.
8. **Колір ядра `#D7FFF0`** лежить константою `SPARK_CORE` в `IntroAnimation.tsx`, не в
   токенах: він існує лише в шейдері.

#### Кільце

- **Пресет `orbit`, а не `cylinder`.** З трьома картками `cylinder` ховає дві задні за
  передньою і показує їх ребром та зворотом (сірі дзеркальні смуги, див. `tune1.png`,
  верхній ряд). `orbit` тримає всі картки лицем до глядача: дві задні читаються як екрани
  й тануть у фоні аркуша.
- Налаштування: `cardWidth 700`, `aspectRatio 1.78`, `gap -280`, `tilt -20`,
  `perspective 1300`, `speed 9`, `depthFade 0.8`, `cornerRadius 20`, `curve 0`,
  `innerShade 0.9`. Два останні в `orbit` нічого не роблять (картки пласкі, зворотів не
  видно) і лишені на випадок зміни пресета.
- **Відʼємний `gap` навмисний.** Компонент масштабує все кільце під ширину контейнера, тому
  зі звичайним проміжком передня картка виходить близько 470px за будь-якого `cardWidth`.
  З `-280` вона близько 600px на 1440 і 490px на 1024.
- `fadeColor="var(--bg)"`: на аркуші це `#F4FFFB`, без хардкоду кольору.
- `autoplay="drift"`, `pauseOnHover`, `snap`, `draggable`, `focusOnClick`, `intro="rise"`,
  `captions` вимкнено.
- Контейнер `.pf-ring`: `position: relative`, висота 520px. Краї кільця розчиняються маскою
  9% зліва і справа.
- Клік по задній картці виводить її вперед. Клік по передній (або Enter на кільці) відкриває
  кейс. Для Florist Shop нічого не відбувається.

#### Інфо-панель

Mono-мітка (`01 / 03`, підпис екрана, домен), назва, опис, теги; праворуч кнопки. Для двох
живих проєктів «Кейс» (головна, `next/link`) і «Відкрити сайт» з іконкою (вторинна,
`https://${domain}`, нова вкладка). Для Florist Shop лише мʼятна позначка «Скоро». Усе на
наявних класах (`.mono-label`, `.tag`, `.btn`, `.pf-soon`) і токенах світлої теми. При
зміні картки текст мʼяко проявляється за 450ms; при reduced-motion одразу.

#### Мобільні й завантаження

- До 1024px лишається сітка карток. Що видно, вирішує CSS (`.pf-grid` проти
  `.pf-ring-slot`), тому при гідрації нічого не стрибає.
- Код кільця завантажується, лише коли ширина від 1024px **і** слот ближче ніж 600px до
  вікна. Місце під кільце зарезервоване наперед (`min-height: 702px` = 520 + 182).

### Сумісність з React 19 / Next 16

Проблем не видно. Обидва файли мають `'use client'`, використовують лише хуки
(`useEffect`, `useLayoutEffect`, `useRef`, `useMemo`, `useState`, `useCallback`), без
`forwardRef`, `defaultProps`, `findDOMNode`. CSS імпортується з компонента звичайним
`import './X.css'`, що в App Router дозволено. Реальний рендер у браузері ще не перевірявся,
це фази 1 і 2.

### ElectricLogo: що показав код

| Питання | Відповідь |
|---|---|
| Що малює | **Лише розряди по контуру.** Сам логотип не малюється: картинка перетворюється на поле відстаней до краю силуету, шейдер малює блискавки вздовж краю. Є пропс `fill` (за замовчуванням 0), який заливає тіло силуету світінням, але кольорів оригіналу не відтворює |
| Формат `src` | Будь-що, що вантажить `<img>`: SVG, PNG, data-URL. Растеризується в 560px по довшій стороні. `crossOrigin = 'anonymous'`, для файлу з `public/` це не заважає |
| Прозорий фон | Не обовʼязковий, але змінює результат. Якщо понад 1% пікселів прозорі, силует береться з альфа-каналу. Інакше фоном вважається середній колір країв картинки, а силуетом усе, що від нього відрізняється |
| `interactive` | Курсор над контейнером підсилює розряди поруч (`cursorRadius` 100px, `cursorIntensity` 0.75). Клік дає імпульс і спалах. Слухачі на контейнері, не на `window` |
| Cleanup WebGL | Є: `cancelAnimationFrame`, відключення `ResizeObserver` та `IntersectionObserver`, зняття слухачів, `WEBGL_lose_context.loseContext()`, видалення canvas. Витоку контексту при розмонтуванні не буде |
| `prefers-reduced-motion` | **Не вимикається.** Рух сповільнюється до 0.2, мерехтіння і додаткові дуги вимкнені, кліки ігноруються, але анімація йде. Для нас це не проблема: інтро при reduced-motion вже не показується взагалі |
| Без WebGL2 | Тихо повертає порожній `div`, без помилки і без колбека. Потрібен саме WebGL2. Фолбек доведеться визначати в обгортці (власна перевірка контексту або пропс `onRender`, який викликається після кожного кадру) |
| Поява | Логотип проявляється плавно за **1.4 с** після завантаження картинки (константа в коді, пропсом не керується) |
| Навантаження | DPR обмежений 2 і бюджетом 4 млн пікселів. Поза видимістю цикл зупиняється |


### CircularCarousel: що показав код

- Залежностей немає, чистий CSS 3D (`transform`), без canvas і WebGL.
- **Колесо миші:** `preventDefault` викликається лише коли горизонтальна складова більша за
  вертикальну. Вертикальна прокрутка сторінки над кільцем проходить далі, конфлікту з Lenis
  з коду не видно. Перевірю в браузері у фазі 3.
- **Клавіатура:** контейнер `tabIndex=0`, `role="region"`, стрілки перемикають картки,
  Enter і пробіл викликають `onItemClick` для активної. Є `aria-live` область.
- **`onItemClick` спрацьовує на будь-якій картці**, не лише на передній. Щоб клік по
  передній відкривав кейс, а по інших лише виводив уперед, обгортка сама памʼятатиме
  активний індекс з `onChange`.
- **Фокус:** `.circular-carousel:focus-visible { box-shadow: inset … }`. Перекривається
  звичайним CSS без правки компонента.
- **`prefers-reduced-motion`:** компонент сам стежить за медіазапитом; за кодом autoplay та
  intro при цьому вимикаються, перемикання кліком і стрілками лишається. У браузері ще не
  перевірено.
- **Три картки:** радіус кільця рахується мінімум як для трьох елементів, тож кільце
  збереться, але буде рідким: між картками по 120°. Пресети `cylinder` і `orbit` порівняю на
  скріншотах у фазі 1.
- Картинки вставляються звичайним `<img decoding="async">` без `loading="lazy"`. Для вигину
  кожна картка ріжеться на 8 смуг, тобто один скріншот стоїть у DOM щонайменше 8 разів.
